# ADR-006: Evidence Provenance

## Status

Accepted.

## Konteks

Nilai utama project ini adalah mengubah reasoning LLM menjadi temuan yang bisa dipertanggungjawabkan. Temuan tanpa jejak asal-usul — siapa/apa yang menghasilkan observasi itu, dengan versi tool/image berapa, dari request mana — tidak bisa diaudit, tidak bisa direproduksi, dan tidak bisa dibedakan dari hallusinasi. Masalahnya makin serius karena ada banyak sumber observasi: proxy (replay/mutation), validator Docker, tool pihak ketiga (nuclei, nmap), dan provider lokal. Tanpa provenance yang seragam, output tool pihak ketiga bisa "melompat" langsung menjadi finding dan membypass finding lifecycle; tanpa integritas, evidence bisa diubah setelah dibuat tanpa terdeteksi; dan tanpa sanitasi, kredensial bisa ikut terpersist bersama evidence. Selain itu konten target bisa besar dan sensitif — semua itu tidak boleh masuk reasoning context mentah.

## Keputusan

Setiap observasi dan temuan disertai **structured evidence** dalam evidence graph:

```
Target -> Asset -> Endpoint -> Request -> Response
       -> Observation -> Hypothesis -> Validation -> Finding
```

Aturan yang mengikat:

- **Provenance wajib** pada setiap evidence: sumber (provider/validator/tool), versi (image digest, versi tool, versi template/aset untuk tool pihak ketiga), waktu eksekusi, dan referensi execution plan.
- **Evidence integrity**: setiap evidence di-hash (sha256) saat dibuat; audit log bersifat append-only dan menyimpan chain hash sehingga tampering terdeteksi.
- **Sanitasi kredensial terjadi sebelum persist**: setiap evidence, log, dan result discan terhadap kredensial yang aktif sebelum disimpan dan sebelum data menyentuh reasoning context (ROADMAP §23).
- **Finding tidak boleh `confirmed` hanya berdasarkan satu indikasi.** Minimum evidence untuk temuan: baseline evidence, reproduction steps, expected behavior, actual behavior, impact, false-positive analysis, scope reference, confidence, dan sanitized artifact.
- **Output tool pihak ketiga harus dinormalisasi** menjadi `validation-result.json` + evidence berprovenance oleh wrapper di dalam image — tanpa langkah ini, output tool adalah finding ilegal yang membypass finding lifecycle (ROADMAP §13.1).
- **Konteks reasoning tidak menyimpan full body besar**: body di-truncate/di-summarize di reasoning path; full body disimpan sebagai evidence reference (hash + path), bukan inline (ROADMAP §24).
- **Retention policy**: saat authorization expired atau engagement selesai, data sensitif target di-redact/dihapus sesuai kesepakatan; knowledge yang dihasilkan hanya bertahan sebagai anonymized lesson; tidak ada data target yang persist tanpa batas waktu.

## Konsekuensi

- Setiap finding bisa ditelusuri balik ke rantai observasi konkret: request mana, dieksekusi oleh komponen apa, dengan versi berapa — audit dan reproducibility menjadi properti bawaan, bukan kerja tambahan.
- Perbedaan "observation" (validator/proxy/tool) dan "interpretation" (Hermes) tegas: validator menghasilkan observasi, Hermes menafsirkan — status final vulnerability tidak pernah ditentukan oleh tool.
- Jalur bypass lifecycle tertutup: hasil tool tanpa normalisasi + provenance tidak bisa masuk sebagai temuan.
- Tamper-evidence memberi dasar kepercayaan pada evidence saat report dibahas dengan pemilik target atau program bug bounty.
- Trade-off: setiap jalur eksekusi wajib memproduksi evidence dengan skema yang sama — provider baru/tool baru harus membangun normalisasi, bukan hanya menjalankan tool; dan sanitasi menambah langkah di jalur persist.
- Biaya penyimpanan konten besar terkendali karena full body hanya disimpan sebagai evidence reference dengan hash, bukan disalin ke konteks reasoning.
